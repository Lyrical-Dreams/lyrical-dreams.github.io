Operational watch items

Not broken, just easy to forget under pressure.

Network
Home public IP is dynamic. Both WireGuard configs hard-code the home's public IP as the endpoint. Check for an ISP reassignment first if remote access ever stops working after an outage.
Certificates
Re-check HTTPS trust after any full restart. The self-signed root cert has needed re-installing on the phone before after a full reboot.
Access scope
WireGuard gets you into Jellyfin, not the tunnel box itself. Administering that container always means being on home WiFi first.
Autostart
Guest autostart has failed silently once before. Worth a glance at the Proxmox UI after any host restart rather than assuming both guests came back up.

What's next

Tier 1 is done; these are the Tier 2 items up next, at your own pace (bigger Tier 3 upgrades come after).

Cosmetic hostname fix on CT 101 ~5 min

Shows as CT101 instead of wireguard. Purely cosmetic; hostnamectl set-hostname wireguard whenever it's worth the two minutes.

Set up Dynamic DNS for the home WAN IP ~20–30 min

WireGuard configs currently hard-code the raw public IP, which breaks silently if the ISP ever reassigns it. A free DDNS service gives WireGuard a hostname instead, so it's one less thing to remember.

Move Jellyfin's HTTPS cert to a real trusted one depends on DDNS above

A real Let's Encrypt cert via DNS-01 challenge (once DDNS exists) removes the self-signed cert's re-trust-after-every-reboot gotcha entirely.

Xfinity Bridge Mode ~15–20 min, router-side

Eliminates the double-NAT (Xfinity gateway + Orbi) and the "which WiFi network" ambiguity. No new hardware needed.

Verify backups actually restore ~30–45 min

Spin up a scratch VM/CT from the latest backup-momentus snapshot and confirm it boots with data intact — quick enough not to wait for Tier 3.

Reconsider CT 101's SSH scope (optional) ~10 min if wanted

The WireGuard tunnel currently reaches Jellyfin but not CT 101 itself, so tunnel administration always needs home WiFi. Only worth changing if remote CT 101 admin becomes something actually needed.

Looking further ahead: Tier 3 now includes a network-wide DNS sinkhole and blocklist setup (Pi-hole or AdGuard Home) for ad/tracker blocking on every device, tightening the docs-to-site automation toward real-time instead of twice-daily, photo storage / file sync (moved here from Tier 2, bigger project than a quick task), lightweight monitoring/alerting for VM 100 and CT 101 (e.g. Uptime Kuma), expanding the library beyond movies into TV and music, a budget GPU for Jellyfin hardware transcoding, GPU passthrough for a Windows gaming VM, and eventual network segmentation (VLANs).

Input-Capture Detection Lab

security research

C++ · Windows API · Winsock2

A self-directed research project studying how endpoint monitoring tools detect keylogging behavior, built and run entirely in an isolated virtual lab I controlled end to end.

  • Built a keystroke-capture tool in C++ using low-level Windows API hooks, to understand exactly what signals this class of software leaves behind on a system.
  • Ran the tool exclusively in a sandboxed VM with no network access, generating over 200 hours of controlled test data across a range of input types.
  • Focused the analysis on detection: mapped which behaviors triggered antivirus and EDR alerts, and documented indicators of compromise that defenders could use to flag similar tools.
  • Wrote up findings as a lab report connecting the technical behavior to practical detection guidance, rather than evasion.

Research context only. Built and tested in an isolated environment, never deployed outside the lab.
