Recent progress

Library growth, a second ripping path, a safer ripping routine, TV seasons and multi-disc movies, and some debugging worth keeping.

✓ Second ripping path: rip on a laptop, transfer later — done Oct 16-20 completed

Discs can now be ripped away from the server: MakeMKV for Windows on a laptop with a USB DVD drive, then moved to the media VM with rsync over SSH from WSL. That added 16 movies (99 GB). The first transfer died mid-file overnight (broken pipe, rsync exit 255); the rerun used SSH keepalives inside tmux, resumed cleanly from the partial file, and a rsync --checksum dry run afterward showed no file content differing. Both halves are written up as repeatable runbook sections.

✓ Jellyfin library bug traced down to the database — done Sep 25 completed

The Movies library threw a "Found duplicate path" error and about 49 movies were invisible even though they existed on disk and in the database. Two causes: a duplicate top-level media folder with an orphaned database row, then a stale TopParentId in Jellyfin's SQLite schema pointing at a folder identity that no longer existed. Fixed with a backed-up, scoped UPDATE and a container restart, no rescan needed; the diagnostic path is documented for next time.

✓ Ripping toolchain kept current — done Oct 8-9 completed

When the old MakeMKV build expired, rebuilt it from source on the media VM (now v2.0.0), and corrected the optical-drive device path after finding the VM exposes both an empty virtual DVD drive and the real passed-through one.

✓ Safer ripping routine: stage, verify, then publish — done Oct 9 completed

A few pasted-command mishaps (a rip started by accident straight into the live library, one aimed at a folder that didn't exist yet, one blocked by root-owned permissions) led to a new routine: rip into a staging folder outside the Jellyfin library, check the file's size and duration with ffprobe, then move it into place and eject as separate steps, so a half-written file never shows up in the library. The same routine covers a two-sided DVD: rip each side separately, then append the halves with mkvmerge. Along the way I traced a wrong-title match in Jellyfin to the metadata database filing that title as a TV miniseries, which a movie library can't find. All written up as repeatable manual sections.

✓ Joined a two-part disc without trusting the file size — done Sep 12 completed

A home-recorded DVD scanned as two titles (53 and 88 minutes). I played each on another computer to confirm they were two halves of one film, ripped both, and joined them with mkvmerge. The first join looked right (the same 2.2 GB) but ffprobe reported only the 88-minute half: without mkvmerge’s append flag, the second file’s tracks are stacked beside the first’s instead of following them. Rerunning with the flag gave 2 hours 21 minutes, and the check went into the manual as duration, not size.

Scripted TV seasons and multi-disc movies — in progress, Sep 29 - Oct 2 in progress

Extended the ripping routine to discs that don't fit in one file. A small helper script rips each TV episode into its own temporary folder and renames it to the Show - S01E01.mkv layout Jellyfin expects; each disc's scan is checked for the “Play All” title (its length is the sum of two episodes) so episodes aren't duplicated. Game of Thrones season 1 episodes 1-4 are verified by duration so far, with the rest underway. Two-sided and two-disc movies are ripped part by part into a scratch folder outside the library, joined with mkvmerge’s append mode and checked with ffprobe before anything touches the library; a nearly four-hour film joined in about two minutes. A damaged disc that kept returning unrecovered read errors was stopped and ejected rather than forced.

Operational watch items

Not broken, just easy to forget under pressure.

Network
Home public IP is dynamic. Both WireGuard configs hard-code the home's public IP as the endpoint. Check for an ISP reassignment first if remote access ever stops working after an outage.
Certificates
Re-check HTTPS trust after any full restart. The self-signed root cert has needed re-installing on the phone before after a full reboot.
Access scope
WireGuard gets you into Jellyfin, not the tunnel box itself. Administering that container always means being on home WiFi first.
Autostart
Guest autostart has failed silently once before. Worth a glance at the Proxmox UI after any host restart rather than assuming both guests came back up.
Disk space — resolved
VM 100's root disk crashed Jellyfin three times (Sep 25 & 26); fixed Sep 26. Root cause was two-fold: Jellyfin's uncapped transcode cache (now on a 2-hour cron cleanup) and 15GB of unallocated LVM space on the 32GB virtual disk that was never extended into the root filesystem (now extended live, no downtime — 30GB total, 45% used). Kept here as a reminder of what to watch, not an active problem.

What's next

Tier 1 is done; these are the Tier 2 items up next, at your own pace (bigger Tier 3 upgrades come after).

✓ Cap Jellyfin's cache / add a cleanup schedule — done Sep 26 completed

Jellyfin's own "Clean Transcode Directory" task only clears files >1 day old (not adjustable) — that's why it never prevented the crashes. Added a cron job on VM 100 instead: docker exec jellyfin find /cache/transcodes -type f -mmin +60 -delete every 2 hours, run inside the container to dodge the root-ownership permission issue. Smoke-tested clean; watching over the next day or two to confirm it holds.

✓ Confirm backup, then grow VM 100's root disk — done Sep 26 completed

Found and fixed two backup bugs along the way: the job was actually running monthly (not weekly, as previously documented), and the Momentus drive had no /etc/fstab entry so a plain mount -a after replugging it did nothing. Fixed both (fstab entry with nofail, schedule changed to biweekly — 1st & 3rd Thursday, 5pm). Disk grow turned out simpler than expected: 15GB of LVM space was already provisioned on the 32GB virtual disk but never allocated — extended live with lvextend + resize2fs, no Proxmox-side resize, no downtime. Root filesystem now 30GB, 45% used.

✓ Cosmetic hostname fix on CT 101 — done Sep 26 completed

Fixed properly via pct set 101 --hostname wireguard from the Proxmox host (not just hostnamectl inside the guest — CT 101's hostname is managed by Proxmox's own LXC config, so a guest-only change would've reverted on the next restart), then a quick pct reboot 101. Confirmed persistent.

Input-Capture Detection Lab

security research

C++ · Windows API · Winsock2

A self-directed research project studying how endpoint monitoring tools detect keylogging behavior, built and run entirely in an isolated virtual lab I controlled end to end.

  • Built a keystroke-capture tool in C++ using low-level Windows API hooks, to understand exactly what signals this class of software leaves behind on a system.
  • Ran the tool exclusively in a sandboxed VM with no network access, generating over 200 hours of controlled test data across a range of input types.
  • Focused the analysis on detection: mapped which behaviors triggered antivirus and EDR alerts, and documented indicators of compromise that defenders could use to flag similar tools.
  • Wrote up findings as a lab report connecting the technical behavior to practical detection guidance, rather than evasion.

Research context only. Built and tested in an isolated environment, never deployed outside the lab.
